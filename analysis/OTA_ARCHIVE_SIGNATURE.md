# Signed OTA archive trailer

Follow-up: [BOOT_RECOVERY_AND_METADATA.md](BOOT_RECOVERY_AND_METADATA.md)
distinguishes the archive's 48-byte metadata from the 64-byte metadata used by
main/factory/sensor members, and records further fields and validator paths.

The OTA with SHA-256
`ee06079610eaf9b4ffbe35c7a6ddc604ee2aba00c3a66d85101ed2a6556d6df4`
has its ZIP end-of-central-directory record at file offset `0x711f8f1`.
The record has no ZIP comment; 112 bytes follow it. Those bytes begin with
`HMZPSIGN`, matching the magic words checked by recovery candidate
`0x80d18598` under the experimental AndeStar mapping. That function reads
48 bytes from 112 bytes before the indicated end and checks two magic words
before delegating to another metadata parser.

An independent Python `cryptography` check verifies the final 64 bytes as an
ECDSA secp256k1 `r || s` signature over SHA-256 of every preceding archive byte,
including the 48-byte metadata block. The public key is the same embedded key
already used for the five signed image members. A changed byte halfway through
the archive causes the check to fail. See `archive_signature` in
[ota-signatures.json](ota-signatures.json), generated by the updated
`analysis_scripts/verify_ota_signatures.py`.

This proves internal consistency with that embedded key. It is not independent
identification of the signer, nor observation of the watch's enforcement or a
working installation/recovery path. The exact metadata field definitions remain
unresolved. The original ZIP and complete trailer stay under ignored firmware/.
